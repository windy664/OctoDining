# 作品任务：下课后快速决定今晚吃什么

## 用户问题

学生放学或下班后已经很累，还要翻菜单、比较价格、猜店铺是否营业，反复决定“今晚吃什么”。他们希望少做选择，并得到一个现在可能买到、预算合适的建议。

## 输入与输出

- 用户输入预算、预计到店时间和已支持的避辣要求；也可选择 A1–A6 预算档。
- 应用从菜单快照里筛当前餐次、预算内、按快照营业时段可能营业的商品。
- 先给一个首选和最多两个备选，列出商品、店铺、快照营业时间和价格。
- 用户点选后，本地记录为今晚计划；不代下单或付款。一周餐表作为辅助流程保留。

## 完成标准

1. 每个候选都能回溯到菜单快照、没有超过预算，并且快照营业时段覆盖用户给出的到店时间。
2. 用户能清楚看到为何出现这些候选，并通过一次点击作出选择。
3. 没有匹配项时不造假，提示调整预算或到店时间；不能理解的饮食要求明确说明。
4. 每周辅助流程的七天餐表也逐日核对预算与商品来源。

## 数据和非目标

当前使用 1,497 条本地清洗菜单快照。它没有实时库存、路程、评论或当前营业状态。首版只解析预算、到店时间与避辣；不推断过敏原、素食、营养或健康效果。数据再分发许可尚待确认。

## 当前范围

比赛入口已改为 Rinx Mini Apps 的 OctoScript bundle。应用通过 `octos.turn.start` 将用户偏好和本地规则筛出的候选交给宿主 Agent；候选筛选和用户确认仍由应用完成。OctoSense `card-host` 已通过 bundle admission 和 UI 首帧检查，但它不提供 Rinx 的 Agent 服务，真实 Agent 响应、比赛账号导入及演示材料仍待验证。`meal_planner.html` 和 Rust CLI 是备用原型，不是参赛主入口。详见 `CONTEST_READINESS.md`。
