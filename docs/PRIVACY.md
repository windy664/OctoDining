# OctoDining 数据与隐私说明

更新：2026-10-10；对应应用版本 1.9.0。实际网络与模型处理还取决于使用的 OctoSense 宿主。

每月可支配生活费、非餐饮固定开销与缓冲金存于应用本地 `profile.json`；语言设置存于 `language.json`。确认的餐表、记录的实付金额和修改写入本地 `plans-a.json` / `plans-b.json`。用户导入的菜单及来源、更新日期存于本地 `custom-menu.json`。口味评价（好吃/不行/换一道）存于本地 `taste.json`，只用于本机推荐，不发送给任何服务。1.9.0 起应用会把“下一餐”摘要发布到本机一览屏（`glance`，卡片只在本设备显示，点开回到本应用）；Agent 请求后应用可能在本地写入最近的模型原始回复与解析记录（`agent-week-*.txt`），餐表确认校验失败时写入 `confirm-fail.txt`，便于核对模型与应用行为。应用没有账号、定位、订单或支付接口，也不跨设备同步。

使用内置食堂菜单时，商品图从 `img.pospal.cn` 加载；图片服务方可获得一般网络请求中的连接信息及所请求的商品图 URL。应用不会向该图片域名发送预算或餐表。用户导入的菜单目前不加载外部图片。离线时内置商品图可能无法显示。

只有用户主动点击“让 OctoSense Agent 比较”时，应用才通过宿主 `octos.turn.start` 发送本次需求、每日与单餐预算、餐次、至多三个候选及当天计划摘要。月生活费、固定开销和缓冲金原值不发送。若宿主使用云模型，这些内容会交给宿主配置的服务商；应用不读取模型密钥。Agent 给建议，保存须由用户确认。

取消或撤销会更新本地记录。当前没有应用内彻底清空或导出数据的入口；删除数据需使用宿主的应用数据管理方式。菜单是快照，不保证现价、库存、营养或过敏原安全。[数据来源与许可](DATA_PROVENANCE.md)中的内置菜单再分发问题仍需核实。
