# 运行时 Agent 任务与责任

目标路线：OctoDining → OctoSense 宿主服务 → 系统 octos。Rinx 是可选宿主。当前请求入口已写入源码，但权限不一致，真实链路尚未验收。

## 分工

| 责任方 | 做什么 | 验证方式 |
| --- | --- | --- |
| 应用 | 读取菜单、预算、时间与已有计划，执行筛选和金额计算 | 候选可追溯，金额与规则可重复核验 |
| Agent | 理解偏好、比较已有候选、说明取舍，基于计划提出调整 | 建议引用有效候选和当前条件，不编造数据 |
| 用户 | 允许或拒绝助手使用，调整条件，确认具体计划变更 | 授权和确认在界面可见 |
| 应用 | 确认后写入，读回核验，更新计划预算 | 重启可恢复，修改/取消不重复计入 |
| 宿主 | 配置 provider，管理密钥、权限和 Agent 会话 | 应用无法读取密钥，服务不可用时返回明确状态 |

“编码 Agent 帮忙写过程序”“调用模型收到文字”和“应用完成整个任务”是不同的证据层次。

## 当前实现与差距

源码用本地规则选择最多三个不同店铺候选，将预算、到店时间、描述和候选发送给 `octos.turn.start`，展示返回文本。用户点击候选后调用 `fs.write` 写入 `tonight.json`。

目前尚无：计划历史读取、返回建议的结构化核验、保存后读回、预算更新和变更追踪。错误分支统一回退到本地预览，没有展示服务的具体失败原因。候选筛选不等于全菜单的最优搜索；模型文本也未被强制限制只能引用给出的候选。

## 数据和权限

目标权限为基本存储与界面实际使用的精确助手服务名。**当前 manifest 仍是 `storage`、`net`，不符合源码调用。** 修复和联调见 [P0](ROADMAP.md#p0修复应用包并验证宿主)。

发送给模型的内容应限于用户本次偏好、候选和与任务有关的计划摘要，隐私说明需写明这些内容会经宿主交给模型提供方。密钥留在宿主，应用包不直接携带模型或菜单采集凭据。

## 失败与接管

- 没有可核验候选时停止推荐，不凭空生成菜名或价格。
- Agent 不可用时显示本地规则模式，仍可让用户手动选择；诊断不得泄露凭据。
- 用户拒绝或修改条件后，旧建议不再具有写入效力。
- 保存失败时不显示“已保存”；重试与重复确认不产生重复计划。
- 菜单快照没有实时库存、营养和过敏原依据。关键词避辣不构成食品安全或健康保证。

这些行为是验收要求，尚未全部实现。验收记录应同时保存成功路径和失败路径，明确区分规则输出、模型输出与最终计划状态。
