| 项目 | 证据或缺口 |

| 产品目标 | 面向预算有限的人进行餐饮规划；见 BRIEF |

| 商店资料 | `listing.json` 仍是 notes 模板、占位发布者和 Android 平台声明；不能当作真实上架资料 |
| 截图 | 仓库存在历史图片，未核验与当前版本的一致性；不作为当前成功证据 |
| 数据许可 | 采集时间、来源凭据与公开再分发授权需补全；代码许可见 `LICENSE-CODE` |

## 第一条验收任务

预算 ¥20、到店 18:30、关键词避辣 → 显示有来源的候选 → 系统 Agent 给出可核验建议 → 用户确认 → 保存并读回 → 重新打开显示同一计划 → 修改或取消后金额正确。

另测无候选、未知营业时间、未支持偏好、拒绝授权、模型不可用、请求失败和存储失败。后续增加历史去重及预算变化后的重新规划。

## 验证记录的要求

每次记录应用提交号、bundle 摘要、宿主及依赖版本、平台、命令、结果与截图/日志路径。特别区分：

- `hub check`：包的基础预检。
- `card-host`：应用界面和普通交互测试。
- OctoSense Shell：实际目标宿主加载与权限检查。
- 系统 Agent：真实请求、响应、确认操作与结果核验。
- HTML/Rust 检查：历史原型的算法回归。

过去的运行结果保留在 [历史接续](CONTINUATION.md)，不移植为本次完成记录。
