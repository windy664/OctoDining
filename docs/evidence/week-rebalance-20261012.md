# OctoDining 1.11.0 超支重平衡与实付回流验收

2026-10-12，Linux card-host 隔离应用数据（`scripts/test-rebalance.py`，自动驱动真实 OctoScript 应用）。画面来自测试运行中的 Makepad framebuffer，经人工查看。本页证明本地规则引擎闭环：读状态 → 提方案 → 用户确认 → 执行 → 读回核验；不涉及模型调用。

- 本周预算卡：¥140.00 预算已计入 ¥197.00 · 140%，八段进度条满格——**已吃餐次按实际支付计入**，待吃按计划价；
- 「省钱调整方案」卡：本周超支 ¥57.00；调整 3 餐最多省 ¥18.00，含取消 3 餐加餐或早餐。已吃餐次不动，确认后才写入。逐条列出「取消 玉米鲜肉蒸饺 ¥6.00（省 ¥6.00）」等；底部「应用并核验 / 忽略」由用户决定。

测试构造：昨日一餐过了计划时间未确认（触发「未打卡跟进」提醒），整周草案确认后把今天一餐按 ¥99.00 实付打卡（触发周级超支）。自动断言：

- 未打卡提醒出现在首页「需要留意」：过去 7 天有 N 餐未确认，引导打开对应日期取消；
- 周超支提醒出现，「帮我调整超支 ›」按钮仅在周超支时可见；点击进入一周餐表并给出方案；
- 方案面板跟随中英切换（Over budget by ¥… / Drop … (save ¥…)）；
- 点「应用并核验」后状态栏报告「已调整 3 餐，省下 ¥18.00，并读回核验」；读回 plans 文件确认：3 处早餐按计划移除、已吃餐次与实付金额原样、周计入从 ¥197.00 降至 ¥179.00，预算条同步刷新。

设计边界（与草案生成同一原则）：午晚正餐只换更便宜的可选项，从不取消；加餐与早餐在预算紧张时才建议取消；每条调整逐条列出，确认前不写入。

运行：`python3 scripts/test-rebalance.py`（隔离数据、无模型调用）。菜单快照超过 30 天时的「快照过期」提醒另经一次性驱动验证（自定义菜单更新日期 2026-08-01，提示「已有 72 天…以食堂现场为准」）。
