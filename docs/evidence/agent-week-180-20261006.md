# 1.8.0 七日草案 Agent 换餐：实现与 card-host 验收记录

2026-10-06 实现；2026-10-10 完成 card-host 运行验收。1.7.0 的截图与 1.2.2 的真实 MiniMax 回复属于旧版本，不能证明这里的新功能。Shell 内真实模型回复仍未验收。

应用先以本地规则生成七日草案，再从不同日期各找至多两个可换餐，最多覆盖七个日期。备选菜须与原餐次匹配、在默认到店时间营业，且价格不高于原菜；菜单仍是快照。用户输入想调整的口味或安排，应用把原餐、备选、价格、店铺和时段送给宿主 `octos.turn.start`。Agent 只能返回日期编号、替代品编号及理由，空数组表示建议不换。应用检查响应类型、编号范围、同日重复选择、请求代次、草案版本和当前需求；有变动就丢弃旧回复。用户先把提案应用到**未确认草案**，逐项核对后再按“确认整周草案”，沿用预算与时段校验、保存并读回。Agent 无法直接改已确认计划、下单或付款，也不能保证营养或过敏安全。

## 2026-10-10 card-host 验收

10 月 6 日以后环境恢复本地监听能力。合并到 `master` 后首轮运行即暴露一个真实缺陷：`prepare_week_agent_offers()` 在设置草案摘要之前被调用，其中 `summary += weekAgentOffers.len() + ". "` 以数字开头拼接字符串，运行时中止处理器，导致**草案摘要与状态都不显示**（cherry-pick 合并后的构建里基线 `test-week-draft.py` 也失败，对照 8e37d9b 工作树通过后定位）。修复：改为 `"" + len` 起头，并把该调用移到摘要与状态更新之后；见提交 "Fix week draft broken by number-first string concat"。

修复后同一构建依次通过：
