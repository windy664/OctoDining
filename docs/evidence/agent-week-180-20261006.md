# 1.8.0 七日草案 Agent 换餐：源码与待验收记录

2026-10-06。此页记录**实现和静态检查**，不是实机验收或模型成功证据。1.7.0 的截图与 1.2.2 的真实 MiniMax 回复属于旧版本，不能证明这里的新功能。

应用先以本地规则生成七日草案，再从不同日期各找至多两个可换餐，最多覆盖七个日期。备选菜须与原餐次匹配、在默认到店时间营业，且价格不高于原菜；菜单仍是快照。用户输入想调整的口味或安排，应用把原餐、备选、价格、店铺和时段送给宿主 `octos.turn.start`。Agent 只能返回日期编号、替代品编号及理由，空数组表示建议不换。应用检查响应类型、编号范围、同日重复选择、请求代次、草案版本和当前需求；有变动就丢弃旧回复。用户先把提案应用到**未确认草案**，逐项核对后再按“确认整周草案”，沿用预算与时段校验、保存并读回。Agent 无法直接改已确认计划、下单或付款，也不能保证营养或过敏安全。

已通过：`python3 scripts/build-octos-bundle.py`、本地 Makepad `ScriptParser` 解析 `bundle/main.splash`、`tools/octo check bundle` 的 unsigned 包预检。预检只验证包结构，不执行页面交互。

未通过运行验收：当前隔离执行环境创建本地 socket 时返回 `Operation not permitted`，`python3 scripts/test-week-draft.py` 在 `tools/octo run` 启动前失败；直接启动宿主又无法连接本机图形会话。因此还没有 1.8.0 的 Agent 回复、应用草案、人工确认、保存读回或新截图。不能把这版作为已经跑通的比赛演示。

下一次在可运行宿主的环境中，应按同一个 bundle 依次验证：生成草案无提前写入 → 输入跨日换餐需求 → 首次授权 → 真实 Agent 回复及编号/理由 → 应用到草案但文件仍不变 → 用户确认整周 → 文件读回与预算核验；再分别验证拒绝授权、模型错误、无效 JSON、过期回复和用户舍弃草案。记录宿主与 provider 版本、截图和日志后才能更新演示视频。
